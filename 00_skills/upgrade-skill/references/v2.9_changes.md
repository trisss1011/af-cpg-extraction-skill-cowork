# v2.9 변경 명세 (cpg-data-extraction)

> 본 파일은 upgrade-skill이 마스터를 v2.8 → v2.9로 업그레이드할 때 적용하는 변경 항목을 정의한다.
> 버전 식별: `_meta` 시트의 `spec_version` 값이 `2.9` 미만이면 본 파일의 변경을 적용.
> 적용 후 `_meta`에 `spec_version=2.9`, `last_upgrade=<YYYY-MM-DD>` 기록.

## v2.9 변경의 성격

v2.9도 **열 구조 변경이 없는 값·명명 규칙 보강 + 소급 재코딩** 릴리스다 (48열 유지). 출처: Decision Log §2.C-10·§1.U-03.
- 자동 처리: `spec_version` 갱신 + TER importance 일괄 `Important` + TER 코드 **확정 매핑만** 정규화.
- 핵심 소급(TER 4종 중 기준 모호 행·냉동소작 코드 8)은 원문/판정기준 대조가 필요해 **사람 확인 항목**.
- 멱등성 보장.

> **자동화 한계 (설계 메모)**: TER을 `TER-ECG`(체표) vs `TER-Holter`(动态)로 가르는 것은 outcome_original/notes에 판정기준이 **확정 표기**된 경우만 자동. 그 외는 단순 `TER` 유지 또는 8단계 사람 확인. SKILL 문서 경량화(frontmatter·인라인 버전태그·한약 §3A 중복)는 마스터 데이터와 무관 — upgrade 항목 아님.

## 자동 처리 룰 상세

### 1. `spec_version` 갱신

- `_meta` 시트의 `spec_version` 값을 `2.9`로 덮어쓴다.
- `last_upgrade`에 오늘 날짜, `last_actor`에 현재 upgrade-skill 버전(`upgrade-skill v2.9.1`) 기록.
- 멱등: 현재 값이 이미 `2.9` 이상이면 skip.

### 2. TER importance 일괄 `Important`

- 아웃컴 시트에서 outcome_std가 TER 계열(`TER`, `TER-Holter`, `TER-ECG`, `TER-TCM`, 및 구 표기 `TER-홀터`/`TCM syndrome TER` 등)인 행의 F열(importance)을 **`Important`로 일괄 정규화**.
- 기존에 `Critical`(예: 心电图 계열 일부)·공란이던 TER 행도 `Important`로 통일.
- 멱등: 이미 전부 `Important`면 변화 없음.

### 3. TER 코드 정규화 (확정 매핑만 자동)

아웃컴 시트 outcome_std가 다음 **확정 매핑**에 해당하면 자동 치환:

| 구 표기 | 신 표기 |
|---|---|
| `TCM syndrome TER`, `TER-TCM(중의증후)` 변형 | `TER-TCM` |
| `TER-홀터`, `TER_holter`, `TER-Holter` 변형 | `TER-Holter` |
| `TER-심전도`, `TER_ecg` 변형 | `TER-ECG` |

- 표기만 다른 동일 의미는 자동 통일. 원문 용어는 D열(outcome_original)에 그대로 보존.

## 사람 확인 항목 검출 룰 (자동 변경 X)

### A. TER 기준 모호 행 (§2.C-10)

체표 심전도(`心电图`) vs 동태(Holter, `动态心电图`) 구분이 outcome_original/notes로 **확정되지 않는** TER 행.

**검출 알고리즘**:
1. outcome_std가 `TER`·`TER-ECG`·`TER-Holter`인 행 수집.
2. D열(outcome_original)·notes에 `动态`/`Holter`/`24h`/`体表`/`心电图` 신호가 **불명확하거나 상충**하는 행을 후보로 표시.

**8단계 표시**: study_id, 행번호, outcome_std 현재값, D열·notes 원문.
**작업자 처리**: 원문 확인 후 4종 중 확정(`TER-ECG`/`TER-Holter`/`TER-TCM`) 또는 기준 불명이면 단순 `TER` 유지.

### B. 냉동소작 → comorbidity_code 8 (§1.U-03)

v2.9에서 냉동소작(cryoablation)은 RFCA(코드 1)와 별개 코드 8.

**검출 알고리즘**:
1. comorbidity_text(V열)·notes에 `冷冻`/`冷冻球囊`/`cryo`/`cryoballoon` 신호가 있는 행 수집.
2. comorbidity_code에 `8`이 없거나 `1`(RFCA)로만 코딩된 행을 후보로 표시.

**8단계 표시**: study_id, 행번호, comorbidity_code 현재값, V열 원문.
**작업자 처리**: 원문 시술명 확인 후 냉동소작이면 comorbidity_code에 `8` 부여(RFCA 코드 1과 구분). 알려진 케이스: **148(Liu 2019)** 经皮冷冻球囊导管消融.

## 멱등성 보장

- 자동 처리: `spec_version`이 이미 `2.9` 이상이면 skip. TER importance/코드 정규화는 이미 4종·`Important`면 변화 0.
- 사람 확인 항목: 8단계 처치 후 검출에서 자연히 제외(코드 8 부여 시 §B에서 빠짐, TER 코드 확정 시 §A에서 빠짐).
- "건너뛰기" 항목은 다음 세션 재실행 시 다시 등장.
