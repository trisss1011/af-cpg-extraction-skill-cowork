# v2.7 변경 명세 (cpg-data-extraction)

> 본 파일은 upgrade-skill이 마스터를 v2.6.1 → v2.7로 업그레이드할 때 적용하는 변경 항목을 정의한다.
> 버전 식별: `_meta` 시트의 `spec_version` 값이 `2.7` 미만이면 본 파일의 변경을 적용.
> 적용 후 `_meta`에 `spec_version=2.7`, `last_upgrade=<YYYY-MM-DD>` 기록.

---

## v2.7 변경의 성격

v2.7은 **열 구조 변경이 없는 의미·기재 규칙 보강 + 소급 재분류** 릴리스다 (v2.6.1과 동일하게 48열 유지). 따라서:
- 자동 처리 가능한 항목은 제한적 — `spec_version` 갱신 + `KM+WM_vs_KM` exclude 마킹 2건.
- 핵심 변경 대부분은 **사람 확인 항목** — 선정기준(inclusion)·처방 구조·"확실/추정" 구분 등 **원문에만 있고 마스터 셀에는 없는 정보**가 판단에 필요하기 때문. 마스터 셀만으로는 검출(후보 표시)까지만 가능, 적용은 8단계 인터랙티브.
- 멱등성 보장: 같은 마스터를 두 번 실행해도 안전.

> **자동화 한계 (설계 메모)**: 본 스킬은 마스터 엑셀의 셀 값만 읽고 원문 PDF를 보지 않는다. comorbidity 코드 2/7, setting, 처방 합침/분기 판단은 inclusion 기준·처방 구조 원문이 있어야 하므로 자동 변경하지 않는다(검출만). 자동 변경은 셀 값만으로 100% 결정 가능한 `KM+WM_vs_KM` 마킹에 한정한다(보수적 방침, 2026-06-01 합의).

기존 v2.6.1 마스터는 헤더만으로는 2.6.1 vs 2.7 구분이 불가능하므로(둘 다 48열), `_meta`의 `spec_version`으로만 판별한다. `_meta`가 `2.6.1` 미만이면 v2.6.1 명세를 먼저 통과한 뒤 본 명세를 적용.

## 자동 처리 룰 상세

### 1. `spec_version` 갱신

- `_meta` 시트의 `spec_version` 값을 `2.7`로 덮어쓴다.
- `last_upgrade`에 오늘 날짜(`YYYY-MM-DD`), `last_actor`에 `upgrade-skill v1.3` 기록.
- 멱등: 현재 값이 이미 `2.7` 이상이면 skip.

### 2. `KM+WM_vs_KM` exclude 마킹 (§1.0-04)

v2.7에서 `comparison_type == KM+WM_vs_KM`(E: 한방+양방 / C: 한방 단독)은 두 군 차이가 **양방약(WM)**이라 한약 add-on 효과가 아니므로 본 메타분석에서 제외된다. 기존 추출 행을 검출해 **exclude 마킹**(행 삭제 아님)한다.

**검출 알고리즘**:
1. 기본정보 Z열(`comparison_type`)이 `KM+WM_vs_KM`(공백·대소문자 정규화 후 정확 매치)인 행을 수집.
2. 이미 `exclude == Y`인 행은 skip (멱등).

**자동 적용 (마킹만, 삭제 금지)**:
- 해당 행 `exclude = Y`, `exclude_reason = "v2.7: KM+WM_vs_KM 제외 (군간 차이가 양방약, PICO 불일치)"`.
- **행을 삭제하지 않는다** — 3arm 연구에서 같은 study_id의 다른 비교쌍(`KM+WM_vs_WM` 등)을 보존하기 위함. 마킹은 가역적이라 자동 적용해도 안전.
- 같은 study_id에 다른 비교쌍이 있으면(3arm) 미리보기·리포트에 `(3arm: 다른 비교쌍 N개 보존)`으로 부기.

**미리보기 표시**: `KM+WM_vs_KM exclude 마킹: N건 (3arm M건 포함)`

## 사람 확인 항목 검출 룰 (자동 변경 X)

검출만 자동(후보 표시), 실제 셀 수정은 8단계 인터랙티브에서 작업자 응답대로 반영. 표시 항목 공통: `번호 / study_id / 행번호 / 현재값 / 제안값 / 원문 대조 포인트`.

### A. comorbidity 코드 2(심부전) 제거 후보 (§1.U-01)

v2.7에서 코드 2는 **선정기준에 심부전 진단명(心力衰竭/HF/HFpEF 등) 명시 시만** 부여한다. baseline 전수 NYHA·NYHA 단독 inclusion·배제기준 NYHA IV만으로는 부여하지 않는다.

**검출 알고리즘**:
1. 기본정보 U열(`comorbidity_code`)에 코드 `2`가 포함된 행을 모두 수집(복수코드 `2,3` 등 포함).
2. V열(`comorbidity_text`)에 HF 진단명 단서(`心力衰竭`/`心衰`/`HF`/`HFpEF`/`HFrEF`/`heart failure`)가 **없으면** ⚠️ 강한 제거 후보로 표시. 있으면 ⚠️ 약한 후보(원문 inclusion 확인 권장)로 표시.
3. 마스터 셀만으로는 inclusion 명시 여부를 확정할 수 없으므로 **전부 후보로만** 출력.

**8단계 표시**: study_id, 행번호, U열 현재 코드, V열 텍스트, 제안값(코드 2 제거 후 잔여 코드).
**작업자 처리**: 원문 inclusion에 HF 진단명 있으면 유지, 없으면 U열에서 코드 2 제거(다른 코드는 보존). 알려진 케이스: No.88(U=2,3 → 3 검토).

### B. comorbidity 코드 7(노인/노령) 부여 후보 — 보류 (§1.U-02)

v2.7에서 코드 7(노인/노령) 신설. 단 **소급은 보류** — 전체 추출 완료 후 일괄 재추출 시 함께 적용하기로 합의됨. 본 스킬은 참고용 후보만 표시하고 자동 부여하지 않는다.

**검출 알고리즘(참고용)**:
1. P열(연령 데이터)이 있으면 평균/하한 연령 ≥ 60 단서 표시.
2. V열·notes에 `老年`/`elderly`/`노령` 키워드 매치 표시.
3. inclusion 연령 하한은 마스터에 없으므로 확정 불가 → "재추출 시 확인" 안내만.

**8단계 표시**: study_id, 행번호, P열 연령, V열 키워드 매치. **기본 동작: 표시만, 변경 보류**(작업자가 "지금 부여"를 명시할 때만 U열에 7 추가).

### C. setting 추정값 → NR 후보 (§1.M-01)

v2.7에서 입원/외래가 불확실하면 추정하지 않고 NR. v2.6 시절 "收治" 등 표현으로 입원 추정된 행을 검출.

**검출 알고리즘**:
1. 기본정보 M열(`setting`)이 `입원`/`외래`/`inpatient`/`outpatient` 등 비-`NR` 값인 행을 수집.
2. 마스터에는 원문 표현이 없으므로 "확실 명시 vs 추정"을 자동 구분 불가 → 전부 후보로 표시(작업자가 원문 보고 판단).

**8단계 표시**: study_id, 행번호, M열 현재값, 제안값(`NR`).
**작업자 처리**: 원문에 입원/외래 명시 있으면 유지, "收治" 등 불확실 표현이면 `NR`로 변경. 알려진 케이스: 85·99·64·66.

### D. Median/Quartile(IQR) 후보 → 셀 NR + V열 IQR + notes 보존 (§2.일반-03)

Median(Q1,Q3)/M(P25,P75)/IQR 형태 보고는 메타분석에서 제외하고, H~M 셀을 NR, V열(`val2_type`)에 `IQR` 표기, 원문 수치는 notes 보존(IQR→SD 변환 안 함).

**검출 알고리즘** (아웃컴 시트):
1. 다음 신호 중 하나라도 매치되는 행을 수집:
   - `outcome_original`/`notes`에 `median`/`中位数`/`M(P`/`P25`/`P75`/`IQR`/`四分位`/`Q1`/`Q3` 키워드.
   - 값 셀(H~M) 텍스트가 `숫자(숫자,숫자)` 또는 `숫자(숫자-숫자)` 괄호쌍 형태(중앙값(사분위) 패턴).
2. 이미 V열 == `IQR` **그리고** H~M == `NR`인 행은 처리 완료 → skip(멱등).
3. 부분 적용 상태(V열만 IQR거나 셀만 NR)는 보강 후보로 표시.

**8단계 표시**: study_id, 행번호, outcome_std, H~M 현재값, V열 현재값, 제안(H~M→NR / V열→IQR / 원문 notes 보존).
**작업자 처리(보수적: 검출 자동, 적용 8단계 승인)**: median 보고가 맞으면 제안대로 일괄 처치. mean±SD 오검출이면 건너뛰기. 알려진 케이스: No.103(retrofit), No.93(V열 IQR 보강).

### E. 한약 2처방 동시투여 합침 후보 (§3.일반-01)

전원에게 2처방이 동시 투여된 경우 둘을 합쳐 1주처방 1행으로 기재(양 처방 조성·용량 모두 F열 보존). 일부 환자 부처방은 현행대로 note.

**검출 알고리즘** (한의중재_한약 시트):
1. 처방명(C열)/조성(F열)/note에 병용 신호(`合用`/`联合`/`合方`/`＋`/`+`/`并用`/`同时`/`동시`/`병용`)가 있거나, 한 study_id에 처방 행이 2개 이상인 케이스를 수집.
2. 합침 여부·주처방 판단은 조성 대조가 필요 → 후보 표시만.

**8단계 표시**: study_id, 행번호, 처방명, 조성 요약, note.
**작업자 처리**: 전원 동시투여면 1행 합침(F열에 양 처방 보존), 일부 환자 추가면 note 유지. 알려진 케이스: No.77.

### F. 개별화 처방(변증 분기) 후보 (§3.일반-02)

메인 처방 없이 변증(또는 환자 특성)별로 처방이 갈리면 행을 나누지 않고 `개별화 처방 (변증 분기)`로 1행 통합, 분기 내용은 note.

**검출 알고리즘** (한의중재_한약 시트):
1. 처방명(C열)/note에 변증·분형 신호(`辨证`/`辨證`/`随证`/`随症`/`分型`/`分证`/`证型`/`변증`/`변증 분기`) 매치 행 수집.
2. 같은 study_id에 처방 행이 여러 개이고 메인 표식이 없는 케이스도 후보.

**8단계 표시**: study_id, 행번호, 처방명, note.
**작업자 처리**: 변증 분기 구조면 1행으로 통합(`개별화 처방 (변증 분기)`) + note 서술. 알려진 케이스: No.66.

### G. RFCA 후 무처치 대조 재코딩 후보 (§1.0-03)

RFCA(또는 동등 시술)를 양군 모두 시행 후 치료군 한약 / 대조군 무처치(no-drug) 구도는 시술을 WM 처치로 간주해 `KM+WM_vs_WM`으로 포함 처리한다(단건성).

**검출 알고리즘**:
1. Z열(`comparison_type`)이 `KM_alone_vs_placebo`인 행을 수집.
2. AC열(intervention_C_method)/AD열(co_intervention)/notes에 RFCA 신호(`RFCA`/`导管消融`/`射频消融`/`catheter ablation`/`radiofrequency`) 매치 시 ⚠️ 재코딩 후보.

**8단계 표시**: study_id, 행번호, comparison_type 현재값(`KM_alone_vs_placebo`), 제안값(`KM+WM_vs_WM`), RFCA 매치 근거.
**작업자 처리**: 시술 양군 시행 확인 후 `KM+WM_vs_WM`으로 Z열 수정. 알려진 케이스: No.94(张繁之 2022).

## 멱등성 보장

- 자동 처리: `spec_version`이 이미 `2.7` 이상이면 갱신 skip. `KM+WM_vs_KM` 행이 이미 `exclude=Y`면 마킹 skip.
- 사람 확인 항목: 8단계 처치 후 검출 알고리즘에서 자연히 제외(예: Median/IQR 행이 셀 NR+V열 IQR로 처치되면 §D 후보에서 빠짐, M열이 NR로 바뀌면 §C에서 빠짐).
- "건너뛰기"한 항목은 다음 세션 재실행 시 다시 등장 — `.md` 리포트 미처리 목록과 일치.
