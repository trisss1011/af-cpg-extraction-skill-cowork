# v2.9.1 변경 명세 (cpg-data-extraction)

> 본 파일은 upgrade-skill이 마스터를 v2.9 → v2.9.1로 업그레이드할 때 적용하는 변경 항목을 정의한다.
> 버전 식별: `_meta` 시트의 `spec_version` 값이 `2.9.1` 미만이면 본 파일의 변경을 적용.
> 적용 후 `_meta`에 `spec_version=2.9.1`, `last_upgrade=<YYYY-MM-DD>` 기록.

---

## v2.9.1 변경의 성격

v2.9.1은 **열 구조 변경이 없는 버그 패치 + 값 규칙 보강** 릴리스다(48열 유지). 출처: Decision Log §9.7·§1.U-04·§1.0-10.
- 자동 처리: `spec_version` 갱신 + **배제(exclude=Y) 논문의 아웃컴·한의중재_한약 행 소급 삭제**.
- 코드 6(고혈전 색전) 과거지표(CHADS2 등) 부여는 원문 점수 대조가 필요해 **사람 확인 항목**.
- 멱등성 보장(이미 배제 논문 두 시트가 비어 있으면 변경 0건).

> **배제 시트 삭제가 자동인 이유**: 식별 키가 기본정보 J열 `exclude=Y` + A열 `번호`로 마스터 셀만으로 100% 결정 가능하다(원문 대조 불요). 삭제 대상은 "exclude=Y인 번호의 아웃컴·한의중재_한약 행"으로 명확하다. 따라서 미리보기 → "예" 일괄 적용 대상이다. (Decision Log §9.7 — 최근 업그레이드 이후 배제 논문 두 시트가 남아 있던 회귀를 소급 정리)

## 자동 처리 룰 상세

### 1. `spec_version` 갱신

- `_meta` 시트의 `spec_version` 값을 `2.9.1`로 덮어쓴다.
- `last_upgrade`에 오늘 날짜, `last_actor`에 `upgrade-skill v1.5` 기록.
- 멱등: 현재 값이 이미 `2.9.1` 이상이면 skip.

### 2. 배제(exclude=Y) 논문 아웃컴·한의중재_한약 행 삭제

**대상 식별**:
1. `기본정보` 시트를 스캔해 J열 `exclude` 값이 `Y`(공백 제거·대소문자 무시)인 행의 A열 `번호`를 모은다 → `excluded_nums`.
2. `excluded_nums`에 해당하는 번호의 행을 `아웃컴`·`한의중재_한약` 두 시트에서 찾는다.

**삭제 처리**:
- `아웃컴`·`한의중재_한약` 시트에서 A열 `번호`가 `excluded_nums`에 속하는 데이터행을 **역순으로 `ws.delete_rows`** (인덱스 어긋남 방지).
- `기본정보` 행은 **삭제하지 않는다**(배제 논문도 기본정보 + 연분홍 서식은 보존 — PRISMA flow용).
- 행 단위 `delete_rows`이므로 다른 행 서식 손실 없음(merge-skill 원칙과 동일).

**멱등성**: 이미 해당 번호의 아웃컴·한약 행이 없으면 삭제 0건.

**미리보기 표시 예**:
```
배제 논문 아웃컴·한약 행 삭제: 배제 번호 3건(예: 182, 2032, 2047)
  아웃컴 −24행 / 한의중재_한약 −3행 (기본정보 행은 보존)
```

**검증**: 삭제 후 `excluded_nums` 번호가 아웃컴·한의중재_한약 시트에 더 이상 존재하지 않는지 재확인. 기본정보 행 수는 불변.

## 사람 확인 항목 (8단계 인터랙티브)

### Y. comorbidity_code 6 — 과거 평가지표(CHADS2 등) 부여 재확인

- **대상**: V열(comorbidity_text) 또는 원문에 `CHADS2`·구버전 위험도 지표 흔적이 있으나 U열에 코드 6이 없는 행, 또는 코드 6 부여 근거가 과거 지표인 행.
- **판단**: 해당 논문 발표 당시 기준 점수(예: CHADS2 ≥2점)를 충족하면 코드 6 부여(Decision Log §1.U-04). 점수·지표명은 원문/ V열 대조가 필요하므로 자동 변경하지 않고 8단계에서 작업자 확인.
- **표시**: `번호 / study_id / V열 원문 발췌 / 현재 U열 / 제안(코드 6 추가)`.
- 자동 변경 금지 — 작업자 응답대로만 U열 수정.

## 멱등성·안전

- 자동 처리(배제 행 삭제)는 7단계 미리보기 → 명시적 "예"에만 적용.
- 8단계 시작 시 추가 백업 1회.
- 배제 행 삭제는 행 단위 `delete_rows`(역순) — 다른 행 영향 없음.
- 같은 마스터에 두 번 실행해도 변경 0건(멱등).
